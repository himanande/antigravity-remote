このプロジェクト(antigravity-remote)の実装担当です。

## 最初にやること(省略不可)

作業前に必ず読む。**このプロジェクトは「実測で前提が覆る」ことが繰り返し起きているため、過去の実測結果を知らずに実装すると同じ罠を踏みます。**

1. `docs/collaboration.md` — 運用ルール
2. `docs/tasks.md` — 担当タスクの内容と依存。着手時に status/owner を更新してコミットする
3. `docs/findings.md` — **実測済みの事実。特に警告(⚠️)の項目**
4. `docs/decisions.md` — 決定済みの設計方針。**これを再検討しない**

トークンを節約したい場合でも、`findings.md` の ⚠️ 項目と、担当タスクに関係する ADR は必ず読むこと。

## 踏んではいけない既知の罠

`findings.md` に詳細があるが、特に事故が多かったものを挙げる。

- **Durable Object のメモリ上の状態は、本番では1秒未満の間隔でも消える**(退避/eviction)。「忘れると防御や計測が無効になる」状態は必ず永続化する。ローカル `wrangler dev` では退避が起きないため、**この種の欠陥はローカル検証では絶対に見つからない**(F18/F19)
- **Cloudflare の Rate Limiting binding は使わない**。デプロイもバインディング認識も成功するのに本番で発火しなかった(F18)。同様に、**実効を確認できない機構に防御を預けない**
- レート制限の検証は**必ず実WebSocketアップグレードで行う**。curl は `Upgrade` チェックが手前にあるため制限コードに到達しない(F18)
- `wrangler dev` に秘密を渡すのは**シェルの環境変数では不可**。`relay-cf/.dev.vars` に書く(F19)
- node-pty は **N-API 実装なので ABI 安定**。Electron 世代ごとのビルドは不要(F16)
- この環境では**バックグラウンド子プロセスが SIGSTKFLT(144)で落ちる**。`pkill` を他のコマンドと同じ行に束ねると、直前のコマンドが実行されていないのに成功したように見える。**コミットは必ず単独で実行し、`git log` で着弾を確認する**

## 作業の進め方

- 変更は**コミット単位を小さく**保つ。コミットメッセージは日本語で、**なぜそうしたか**を書く(何をしたかはdiffを見れば分かる)
- 検証は `relay-cf/scratch-cf-*.js` の形式に倣う。**「通常の中継が壊れていないこと」を必ず含める**(制限や計測を足すたびに退行しうる)
- 拡張側は `npx tsc --noEmit` と `npm run build` の両方を通す
- リレーを変更したら `relay-cf/scratch-cf-limits.js` を再実行して退行がないか確認する
- 実測した事実は `docs/findings.md` に F番号を採番して追記する。**再現コマンドと確認日を必ず書く**
- 終わったら `docs/tasks.md` の status と結果、進捗ログを更新する

## 判断が必要になったら実装を止める

以下に当たったら、**推測で進めずに持ち帰る**。設計判断は `docs/decisions.md` に ADR として残す必要があり、それは設計担当の仕事。

- 決まっていた前提が実測と食い違った(このプロジェクトでは頻発する)
- 利用者に見える挙動・プライバシー・課金に影響する選択
- 外部サービスへの公開、破壊的操作、費用が発生する操作

持ち帰るときは「何を試して、何が観測され、どの選択肢があるか」を数字付きで報告する。
