# collaboration.md — マルチエージェント共同開発の運用ルール

このプロジェクトは複数のAIエージェント(＋人間 ike3)で開発する。エージェント間ではメモリも会話も共有されないため、**共有すべき情報はすべて git リポジトリの `docs/` に書く**。参加するエージェントはまずこのファイルを読むこと。

## 0. 最初に読む順番(オンボーディング)
1. `docs/requirements_v0.2.md` — 何を作るか(最新の要件)
2. `docs/findings.md` — 実機で確認済みの事実(一次情報)
3. `docs/decisions.md` — なぜこの設計か(蒸し返す前に必読)
4. `docs/tasks.md` — 今どこまで進み、次に何をやるか

## 1. 情報源の役割分担(どこに何を書くか)
| ファイル | 書くもの | 書かないもの |
|---|---|---|
| requirements_*.md | 要件。変更はバージョンを上げて別ファイル(v0.2→v0.3)、旧版に superseded を明記 | 進捗、実装詳細 |
| findings.md | 実機で確認した事実+再現コマンド+確認日 | 推測、設計判断 |
| decisions.md | 設計判断(ADR)。覆すときは新ADR追記、旧に Superseded 印 | 事実の一次記録 |
| tasks.md | タスク状態・担当・進捗ログ | 長い設計議論(decisions へ) |

## 2. 作業の進め方(必須プロトコル)
1. **着手宣言**: tasks.md で対象タスクの `status: WIP` と `owner: <自分の名前>` に更新してコミット。これで二重作業を防ぐ。
2. **owner が空のタスクだけ取る**。既に WIP のものは横取りしない(必要なら tasks の進捗ログで相談)。
3. **こまめにコミット**。1タスク=1ブランチ(`task/NN-短い説明`)を推奨。main へは直接大きく積まない。
4. **完了時**: `status: DONE`、`結果` 行に成果物パス/コミットハッシュ/根拠リンクを記入。新事実は findings、設計変更は decisions にも反映。
5. **ブロック時**: `status: BLOCKED` にして理由と必要な入力を進捗ログに書く。

## 3. コミット規約
- 形式: `[TASK-NN] 種別: 要約`(種別 = feat/fix/docs/chore/exp)
- 例: `[TASK-05] exp: probe sendPromptToAgentPanel argument shape`
- ドキュメントだけの更新は `[docs]` で可。
- 破壊的・外部影響のある操作(公開、外部送信、大量削除)は人間 ike3 の承認を得てから。

## 4. エージェント名(owner 表記)
- Claude 系: `claude-fable`(モデル名で区別可)
- Gemini 系: `gemini`
- 人間: `human:ike3`
- 他エージェントを追加したら、この一覧に追記する。

## 5. 安全上の約束(重要)
- **findings F3/F4 の内部コマンド・language_server を試す作業は副作用を伴う**。稼働中のユーザー作業に影響しないよう、空の会話/使い捨てワークスペースで検証する。
- リモート操作機能(FR-6)は既定オフ。承認系を開放する実装は decisions で認可設計を先に固めてから。
- 秘密情報(トークン・鍵・CSRFトークンの実値)はリポジトリにコミットしない。findings には「存在する」事実だけ書き、実値は書かない。

## 6. 人間(ike3)の関与ポイント
- 要件の方針転換、公開・課金、外部送信を伴う操作、承認系の認可設計は ike3 の判断を仰ぐ。
- それ以外の実装・調査は各エージェントが自律的に進めてよい(tasks.md で可視化されている限り)。
